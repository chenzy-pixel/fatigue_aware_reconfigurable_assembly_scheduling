2026-10-02：V8 HGNN 使用 schema-6 观测。V2 算例、单阶段奖励、固定评测矩阵和当前归一化尺度 `(1089.15,353.27,2.2629)` 沿用主线协议。

| 位置 | 新增字段 | 含义 |
|---|---|---|
| 订单节点、生产候选边 | `estimated_order_slack_norm` | 整个订单预计完成时刻距 horizon 的裕量 |
| 工人候选边 | `estimated_order_slack_norm`、`stage_wait_time_norm` | 关联订单裕量及当前待拆/待装阶段的等待年龄 |
| WAIT 向量 | `minimum_order_slack_after_wait_norm`、`minimum_order_slack_delta_if_wait_norm` | 下一已知事件后活跃订单的最小裕量及变化 |

时间以实例 horizon 归一化，当前 H=240 分钟。裕量为 `(horizon_tick-estimated_finish_tick)/horizon_tick`，保留负值。
新增信息通过订单节点、关系特征和 WAIT 编码进入共享动作 embedding，供 Flow、Cost、Variance 各自独立的 context MLP 使用。
三套直接目标特征及其评分方向保持原定义。

## 预计完成时间

估计覆盖整个剩余工序链：已完成工序跳过；已启动加工、拆卸、安装只计算剩余时间；已知机器和工人占用、资质、疲劳恢复纳入投影。
未释放订单从已知释放时间开始计算。尚未分配的后续工序选预计完成最早的兼容机器，并在单订单链内维护虚拟配置、工人占用和疲劳。

各订单分别投影，跨订单尚未确定的资源竞争与未来策略仍可能使估计偏乐观。无法安全投影的阶段使用有限的 horizon 加一 tick 风险信号。
这些特征是软估计，不作为动作 mask 的可行性证明。

待拆等待年龄从 lock tick 计算，待装从拆卸完成 tick 计算；进入下一阶段后重新计时。
估计按物理状态版本缓存，动作、事件或时间推进后失效。

## WAIT 投影

投影复制可变仿真状态，复用实际事件处理：推进在途工作、工人疲劳、订单释放和工序完成，再计算推进后已释放且未完成订单的最小裕量。
因此裕量变化不等于简单减去 WAIT 时长。释放或完成也可能改变参与最小值的订单集合。
零时间阶段交接保持当前裕量；无活跃订单时使用剩余 horizon 作为中性值。终止观测不再推进已结算的任务。

## checkpoint 与续训

`network_spec` 和 runtime manifest 记录 schema 6 与 `order_chain_action_context_v1`。
同一归一化版本的 schema-5 checkpoint 可以加载：订单输入追加一列、生产候选追加一列、工人候选追加两列、WAIT 追加两列。
相关 HGNN 消息矩阵及输入编码器新增权重补零；Adam 矩阵状态同步扩展，已有权重与状态保留。预测与价值在数值容差内保持一致。

迁移元数据记录源/目标 schema、时间版本、零初始化和源/当前权重哈希。新时间输入需要后续训练才能产生作用。
归一化哈希、网络结构和直接评分契约仍严格校验；不同尺度的旧模型需要单独的尺度迁移实验。

`continue_v2.py` 支持上述观测迁移，自检确认原输入列逐值相同、新增列全零，同时保留源 run 的归一化尺度及固定验证协议。
它仍是从 best 开始的独立微调阶段，优化器、随机状态和训练控制器按该入口的既有规则重新初始化。

## 验证范围

时间特征测试覆盖完整剩余链、部分加工与重构、已知资源占用、阶段等待重置、WAIT 期间进度与订单释放、零时间交接和终止边界。
三个专家的直接分数及 context 输入分开对照；checkpoint 与 Adam 扩展后执行预测、梯度和参数更新检查。
原 schema-5 通道指纹、动作 mask、启发式动作和奖励轨迹保留独立基线，完整 schema-6 指纹另行记录。
