# 订单时间上下文

主线采用 schema12、十维全局向量与十四类关系。冻结尺度、目标与训练设置见[实验协议](experiment_protocol.md)，图输入与评分结构见[当前架构](ARCHITECTURE.md)。

| 位置 | 字段 | 含义 |
|---|---|---|
| 订单节点、生产候选边 | `estimated_order_slack_norm` | 整个订单预计完成时刻距 horizon 的裕量 |
| 工人候选边 | `estimated_order_slack_norm`、`stage_wait_time_norm` | 关联订单裕量及当前待拆/待装阶段的等待年龄 |
| WAIT 向量 | `minimum_order_slack_after_wait_norm`、`minimum_order_slack_delta_if_wait_norm` | 下一已知事件后活跃订单的最小裕量及变化 |

时间以实例 horizon 归一化。裕量为 `(horizon_tick-estimated_finish_tick)/horizon_tick`，保留负值。时间信息通过订单节点、关系特征和 WAIT 编码进入共享动作表示，再与目标候选特征和偏好一起供 shared-head 评分。

## 预计完成时间

估计覆盖整个剩余工序链：已完成工序跳过；已启动加工、拆卸、安装只计算剩余时间；已知机器和工人占用、资质、疲劳恢复纳入投影。未释放订单从已知释放时间开始计算。尚未分配的后续工序选预计完成最早的兼容机器，并在单订单链内维护虚拟配置、工人占用和疲劳。

各订单分别投影，跨订单尚未确定的资源竞争与未来策略仍可能使估计偏乐观。无法安全投影的阶段使用有限的 horizon 加一 tick 风险信号。这些特征是软估计，其数值不决定动作合法性。

待拆等待年龄从 lock tick 计算，待装从拆卸完成 tick 计算；进入下一阶段后重新计时。估计按物理状态版本缓存，动作、事件或时间推进后失效。

## WAIT 投影与截断自举

投影复制可变仿真状态，复用实际事件处理：推进在途工作、工人疲劳、订单释放和工序完成，再计算推进后已释放且未完成订单的最小裕量。因此裕量变化不等于简单减去 WAIT 时长；释放或完成也可能改变参与最小值的订单集合。

零时间阶段交接保持当前裕量；无活跃订单时使用剩余 horizon 作为中性值。物理任务成功、死锁或 horizon 失败后不再投影推进，也不做价值自举。

工程决策保护和 rollout 上限属于采样截断，最终物理状态仍需 critic 自举。生成 WAIT 特征时，仅在投影副本中解除采样截断标记，使下一事件预测能够执行；原环境继续保持停止。否则投影会提前退出，使截断状态的 WAIT 特征丢失未来事件信息。实现见 [project_wait_state](../environment/time_context.py)。

## checkpoint 与验证

当前代码只读取 schema12 的 shared-head checkpoint，并校验编码、尺度、消息函数和目标身份。其他观测版本在加载参数前拒绝；历史结果和模型文件保留，复核时使用其原代码版本。

时间特征回归覆盖完整剩余链、部分加工与重构、已知资源占用、阶段等待重置、WAIT 期间进度与订单释放、零时间交接和终止边界；同时检查时间特征进入生产、工人和 WAIT 共享评分器，以及 checkpoint 回读、预测、梯度和参数更新。
