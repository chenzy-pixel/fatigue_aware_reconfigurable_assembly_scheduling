## 结论

应优先扩充独立瓶颈测试，并建立严格界定的重构时间外推实验。其他瓶颈也有相同的小样本问题。每类 10–20 个独立实例适合作为第一批补证，建议以 20 个为目标；它不是统计充分性的保证。

## test_hard 的合理定义

建议覆盖机器、重构、工人、疲劳、到达压力五类，每类 20 例，总计 100 例，单独报告分层结果。它回答的是各类压力下的可行交付与质量，不能把等配额总体均值当作原训练混合分布的平均性能。

`observed_feasible` 的价值是提供“确有完整、安全、时域内调度”的证据，使策略失败更易解释。当前生成器在静态接受后运行启发式诊断，诊断失败不重采样（`data/generate_orders.py:347`）。因此，只收 observed_feasible 应作为明确的新派生集合协议：保留原始候选池、unknown、筛选原因和接受率，不能静默改变现有生成器或旧测试分母。

避免按待比较 PPO 的成功或优势选样。可预先固定独立参考求解器及预算，保存可重放调度证书；若只以当前启发式成功筛选，应明确结果条件于该启发式可解子集。未获证书者仍是 unknown，不能当作不可行剔除后不留记录。

瓶颈标签是生成配置，实际强度还需诊断：重构次数/时长、机器等待工人、工人竞争、疲劳屏蔽、波次重叠和静态容量负荷分别报告。现有 fatigue 测试两例仅一例出现启发式疲劳屏蔽；validation fatigue 50 例中有 43 例出现。没有触发屏蔽不等于疲劳无影响，但说明仅凭标签不足以证明边界行为。

成本结构也需覆盖：当前 test 的 fatigue 两例都是 labor_dominant，到达压力两例都是 downtime_dominant。建议在每类 20 例中预先安排四种成本结构，例如沿原权重 8/4/4/4；该配额是设计建议，不是已实施事实。先用开发数据确定强度分层，再冻结新测试抽样规则。

## 重构时间外推

当前默认配置及实际主线历史 run `schema12_screen_seed11_20261012_201659_owa_log2/config.json` 的 reconfiguration_bottleneck 范围均为 [1.2,1.6]。生成器现有 OOD 使用 [1.5,2.0]（`data/generate_orders.py:505`），因此包含训练范围内的部分。

1.6 应标为训练边界。可用 1.4、1.6 作为范围内/边界参照，1.8、2.0 作为明确的范围外档位；如连续采样，则要求 scale > 1.6。倍率超界只代表该生成因子外推，不保证每一个最终拆装时长都超过训练值：最终时长还乘 [0.9,1.1] 局部扰动并按时间分辨率量化（`data/generate_orders.py:665`）。

建议先固定 20 个独立基础实例，保持订单、路线、释放、资源、成本和局部扰动相同，仅改变重构倍率，构成 20×4 个配对实例。必须从同一潜在参数生成各档位，不能简单换 split/seed 或重复缩放已量化时间。保存实际倍率、基础实例 ID、局部扰动身份及最终时间范围；当前 sampled_parameters 尚未保存实际 reconfiguration_scale。

各档位分别验证可行性；完整候选池与获证书子集都报告，配对质量比较注明共同可行/共同成功范围。不能在不同档位各自筛出容易样本后把均值差当作纯倍率效应。若专门选择全档位可行的 20 组，应明确这是条件化的配对实验。

先做重构瓶颈底座的压力外推。需要区分一般时间变慢与瓶颈交互时，再增加 balanced 底座对照；现有 OOD 全部采用 balanced 底座，不能替代这一交互检验。

## 其他需要补的部分与优先级

| 优先级 | 补充项 | 依据及用途 |
|---|---|---|
| 高 | 工人、疲劳、机器、到达压力与重构一并分层扩容 | 每类当前仅 2–3 例；随 test_hard 一起解决 |
| 高 | 瓶颈机制及成本结构覆盖 | 标签与实际触发不同，且当前成本结构有空缺 |
| 高 | 多训练种子和按实例配对统计 | 更多偏好或三次采样不能增加独立实例数，也不能替代独立训练模型 |
| 中 | 初始疲劳与资格稀疏外推各 10–20 例 | 直接涉及工人机制；当前 OOD 分别只有 4/3 例，保存的启发式诊断均未出现疲劳屏蔽，资格稀疏 3 例均未出现工人竞争事件 |
| 中 | 其余 OOD 因子分层扩容 | 若论文声称六类泛化，就需逐因子证据，不能只给 20 例混合均值 |
| 条件性 | 重构倍率 × 疲劳/资格稀疏交互 | 单因素结果明确后再做小型因子实验，验证耦合失效，不宜一次混入所有变化 |
| 条件性 | 订单/机器/工人规模外推 | 仅在提出跨规模主张时增加；现有 OOD/stress 不构成此证据 |

## 评价与工程边界

冻结 checkpoint、原训练身份、目标尺度和 best_of_3_v1 交付规则。保留全部三次原始采样、失败原因、交付成功率、共同成功的原始 Flow/Cost/OWA、重构负担及工人等待。保持三端点及低 cost 偏好区域可单独查看；总体均值可能掩盖局部失败。历史 V8/shared-head 诊断已提示低 cost 区域风险，但属于历史目标及单 seed 证据，不能直接外推当前 OWA 主线。

以独立实例作为配对统计与重采样单位；同一基础实例的倍率档位一起重采样。训练种子另外分层报告。20 个实例提供初步区间，不能把 20×66×3 条轨迹当作 3960 个独立样本。

新增集合只在模型/预算冻结后测试，不参与 checkpoint 或学习率选择。若根据其结果修改模型，需将它归为开发集，并保留新的独立确认集。

实现前需处理 split/manifest/CLI 契约：当前 `data/dataset.py:27` 固定 validation/test/ood/stress，新名字不是仅加目录即可。可设计具独立 suite 身份的测试 manifest，或显式扩展 split 支持；两种路径都应独立目录、版本、种子区间及内容去重，并让全部比较方法读取同一套文件。已有 publication 数量配置并不等于数据已物化。

建议首批范围为 100 例 test_hard 加 20 组重构配对外推，先用已有冻结模型评价；是否追加训练或进一步扩大样本，由预先声明的精度目标、置信区间及失效模式决定。
