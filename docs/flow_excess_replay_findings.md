# Flow 比例下界抵扣：方案核查与离线回放

2026-10-08。比例抵扣的数学定义成立，适合作为稠密 Flow 剩余量的候选定义。
本次实现范围为独立回放脚本、回归测试和诊断记录。
协议见 [回放协议](flow_excess_replay_protocol.md)；入口为
`python scripts/replay_flow_excess.py`，结果位于
`result/analysis/flow_excess_replay_20261008/`。

## 数学核查

采用原生加工 tick 下界，记实际计划加工时长为 p，已完成工序抵扣 p_min，
正在加工者抵扣 `p_min*(t-S)/p`。整数 ticks 保证 `p_min<=p`。
一个订单的工序串行、加工开始不早于订单释放，因此：

1. 普通时间推进中 `dF_ex/dt=active_orders-sum_processing(p_min/p)>=0`。
2. 加工完成处，将满额的比例信用转换为 DONE 信用，两者完全相同。
   释放、分派、阶段切换及同 tick 的事件不额外改变 F_ex。
3. 不含失败罚项时 F_ex 连续、非负、分段线性且单调；导数在事件和斜率
   改变处可能不存在，应用“几乎处处非负”，而非“处处可导”。
4. 成功终局抵扣精确为整数 `sum p_min_ticks`，得到
   `F_ex = 总订单等待时间 + sum(p-p_min)`。
5. 在失败/工程截断处，已加工时间应除以原计划 p。已剪裁日志的
   `end-start` 不是这个 p；本次用 `planned_end` 与原生加工函数交叉核对。
   实时环境中加工工序的 `operation.end_tick` 尚为 None，直到完成才赋值；
   p 应从已分派机器的 `estimate_processing_ticks` 读取，或读取机器的计划
   `busy_until_tick-start_tick`，不能用 `operation.end_tick-start_tick`。
6. 保留原 `_flow_penalty` 时，真实失败的终止边界仍有罚项跳变。因此
   包含失败罚项的完整目标不能宣称“处处连续”或“任意零时间变化都不变”。

闭式计算能消除增量浮点累计漂移，但不能消除所有浮点舍入。建议先对
DONE 的整数下界取和，再与最多机器数个正在加工的分数信用合并，最后
统一转分钟。若完全不缓存 DONE 合计，还要遍历/向量化所有工序状态，
不能仅遍历加工中工序；整数 DONE 合计的事件维护本身没有浮点漂移。
成功终值可以用整数证书验证，原 `_flow_integral` 的浮点重建仍需数值容差。

## 总回报与最优策略的适用条件

同尺度、同偏好、同最终目标定义、gamma=1 时，奖励
`r=delta_progress+Q_before-Q_after-lambda*I_failed` 满足望远镜恒等式。
两种扣法对成功轨迹的终值相同，因此成功轨迹的总回报和排序相同。

这不等于无条件证明整个训练问题的最优策略不变：失败/截断的部分加工
信用不同，含失败概率的有限策略族可以得到不同的期望回报。若只比较
成功调度，或能保证最优策略始终成功，则可进一步得到不变性。
本项目 lambda=2 使成功完整轨迹的回报至少为 0，失败回报至多为 -1；
因此在一个已知可行实例上，任何完整成功调度都优于失败调度。
该界并不证明共享参数、部分观测或随机采样策略在所有实例上都能零失败。

此外，从原始 `F/(s+F)` 改成 `F_ex/(s'+F_ex)` 是另一项改变。成功可行
调度的逐实例 Pareto 支配关系保持，但混合偏好的有界切比雪夫解点可以
变化，不能把这个归一化改动也纳入“最优策略必然不变”的陈述。

完成时一次抵扣让质量改善与进度改善集中在同一步，是信用脉冲；由于
质量项仍望远镜相消，没有把某个完成事件额外计入累计目标两次。
比例抵扣改变的是这些脉冲在轨迹上的分配。GAE 的 lambda、critic 误差及
PPO 更新方差仍需要完整训练轨迹验证。

## 本次回放口径

输入为同批 seed11 的 full_flow、full_cost、full_variance 三臂。
20 测试实例 × 3 采样 × 3 臂，共 **180 条**：174 成功，6 失败。
Universal 的该次评估目录没有 `schedule.csv`，未纳入回放。

每条轨迹的原始 Flow 从订单释放/完成重建，工序进度按每订单工序数的
原生权重重建。比例、完成时一次抵扣和前 p_min ticks 全速抵扣均按状态
闭式计算。单纯的 CSV 数学回放没有执行新的环境动作或重训策略。

保存两类离散奖励：

- 事件网格：订单释放、加工开始/结束、实际拆装开始/结束及终止时刻的
  并集。时间推进后统一处理同一时刻的完成事件。
- tick 网格：原生 resolution（本批 0.1 分钟）逐 tick 采样。

真实失败罚项另作为同 tick 的最后一条转移。每种网格都按相同边界比较
两种抵扣法，排除不同网格定义造成的比较偏差。累计回报验证不依赖网格，
单步方差则依赖。

所有来源都用 Flow-only 偏好 `(1,0,0)` 进行反事实奖励计算：
`q=F_ex/(s'+F_ex)`、`r=delta_progress+q_before-q_after-2*I_failed`。
Cost/Variance 是调度的来源，不代表它们原本的 PPO 奖励。未重建重构
lock 到执行的停机费用或承诺方差，因此也没有报告混合偏好奖励。

主诊断尺度 s'=368.31428571428575 来自上一轮 50 个固定验证实例上旧
启发式的 49 个成功样本，未读取测试集进行标定，未写入正式清单。
另保存 s=1089.15 下的相同对照，区分尺度与抵扣分配的影响。

## 核验结果

| 核验 | 结果 |
|---|---|
| 原始 Flow 与历史 `flow_time_objective` 对齐，含原失败罚项 | 最大误差 1.37e-12 分钟 |
| 174 条成功轨迹的比例终值抵扣 | 有理数 tick 证书等于整实例整数 LB |
| 比例/前置抵扣的单调性与非负性 | 所有轨迹、两个网格通过 |
| 比例/前置抵扣中的正 Flow 质量奖励 | 0 次，符合剩余损失单调累积 |
| 成功轨迹两种扣法的总回报一致 | 最大差异 2.23e-16 |
| 全部方法、尺度、网格的奖励恒等式 | 最大误差 6.67e-16 |
| “等待＋慢机器额外耗时”分解，失败保留比例部分 | 180 条均通过，浮点结果误差为 0 |
| 实际部分截断加工 | 6 条失败中 5 条存在；均按计划时长作分母 |

主诊断尺度下，174 条成功轨迹在事件网格中的总奖励方差都降低。

## 代码实施建议的补充核查

用户提出的主体改法合理，但正式接入需补齐以下依赖：

1. `_objective_vector` 可以作为训练目标统一入口，但 `metrics` 的质量计算、
   `eval.py`、`train.py` 汇总和尺度构建仍直接读取报告字段。保留原始
   `flow_time_objective` 后，必须明确哪些函数用新增 excess 字段，哪些用
   原始 Flow，不能只加字段而不更新这些调用。
2. MO-ALNS 的 `OBJECTIVE_FIELDS` 当前首项仍是 `flow_time_objective`。
   档案选解必须用同训练口径，报告与正式 HV 则按预声明评价口径。
3. `project_wait_state` 目前仅推进时间和物理事件，没有执行终止/死锁处理。
   到达失败边界时，仅调用它会漏 `_flow_penalty`。新增回归测试已复现此
   差异；投影必须同步实际 WAIT 后的终止处理，或明确特征仅为罚项前损失。
4. 新增 `flow_mode` 不会自动进入现有契约：`objective_scalarizer_config`
   当前只返回 type/scales/rho。需要显式解析、验证并把语义身份传递到
   network spec、runtime manifest 和 checkpoint。更新清单 hash 能拒绝
   旧清单，但不能代替 flow_mode 的语义校验。
5. 正式 normalization manifest 的来源字段、构建器和加载器需显式区分
   原始 Flow 与 excess 验证均值。当前诊断尺度不是正式冻结清单。
6. 生产候选时长仍有意义，可先保留；新增慢机器额外损失特征另作 schema
   消融。所有未来新时间信用缓存必须纳入 WAIT 投影复制与失效协议。
7. 报告“同一实例 Pareto 集不变”应限定完整可行调度。原始坐标作平移且
   参考点也同步平移时，未归一化 HV 可以不变；采用新的有界归一化与
   固定参考点时，HV 数值一般改变。需先声明主口径，再分别报告。

尚不能证明训练收敛或策略性能改善。
