# Epoch 记录与迁移复核

日期：2026-10-23。

## 已实现

- 正式训练的每个采样/学习批次保存 epoch、逐算例原始指标、三目标有效值与阶段值、决策/交互次数、耗时及分组统计；训练摘要和 checkpoint 标记 epoch。
- 截断使用只读 snapshot，保留 PPO 自举状态，不额外执行环境步。阶段值不会计入完整合法调度的目标均值。
- CSV 直接展开目标列，原始指标保留；缺失计数留空，不写成0。每 epoch 独立 JSON 原子保存。
- DDQN 记录实际 TD loss；单次验证不足以给出最近区间改善结论。
- 正式训练预算统一经 comparison_suite 入口验证，修复直接入口仅检查预算字段真值的问题。
- 当前日志及入口代码纳入 study_identity，旧产物身份保持原样。

## 验证证据

- `tests_final.xml`：49项测试通过，含真实环境完整轨迹、截断快照与交互计数、失败/不安全样本排除、CSV重建、直接训练预算门禁及真实工作进程的直接入口日志检查。
- `verification.json`：PPO、DCAN、Rule-DDQN 各24个真实训练交互步，各5个epoch、10条算例记录；实际梯度更新次数分别10、10、23。每个节点对一个固定验证算例进行完整交付验证。
- `audit.json`：标定54、验证27、测试27，共108个证书全部重放通过；3,836个受保护历史文件哈希一致。
- 小预算集成之后修改了直接训练预算门禁与缺失计数导出；最终49项测试覆盖这两处，所有集成CSV已使用最终导出器重新生成。集成运行身份保留在 `verification.json`，最终源码身份另存 `final_source_identity.json`，不混写。

## 解释边界

这些结果证明所检查链路和记录口径有效，不证明训练收敛、算法优劣或正式预算充分。未启动正式长训练。

每epoch记录训练算例目标；固定验证仍在交互额度20%、40%、60%、80%、100%执行。短预算算例通常未完成，此时完整目标列为空、阶段目标列有值，属于预期行为。论文应结合有效样本数、成功率及固定验证曲线解释训练曲线。

字段和作图口径见 `docs/training_history.md`。
